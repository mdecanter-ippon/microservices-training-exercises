## Context

Currently, our services use manual mapping methods like `UserResponse.from(User user)`. While this works, it has drawbacks:

| Approach | Pros | Cons |
|----------|------|------|
| Manual mapping | Simple, no dependencies | Boilerplate, error-prone, maintenance burden |
| MapStruct | Type-safe, fast, compile-time validation | Build configuration |

**MapStruct** generates mapping code at compile time:

```
┌──────────────────┐    MapStruct     ┌──────────────────┐
│  UserMapper.java │  ─────────────►  │ UserMapperImpl   │
│  (interface)     │   Processor      │ (generated)      │
└──────────────────┘                  └──────────────────┘
       @Mapper                              @Component
```

## Exercise 1: Add MapStruct to user-service

In this exercise, you'll configure MapStruct and create a mapper for user-service.

### 1.1 Add Dependencies

**File:** `user-service/pom.xml`

Add the MapStruct property and dependency:

```xml
<properties>
    <!-- Add this property -->
    <mapstruct.version>1.5.5.Final</mapstruct.version>
</properties>

<dependencies>
    <!-- Add MapStruct dependency -->
    <dependency>
        <groupId>org.mapstruct</groupId>
        <artifactId>mapstruct</artifactId>
        <version>${mapstruct.version}</version>
    </dependency>
</dependencies>
```

### 1.2 Configure the Compiler Plugin

Add the annotation processor to generate mapper implementations:

**File:** `user-service/pom.xml`

```xml
<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <version>3.11.0</version>
            <configuration>
                <annotationProcessorPaths>
                    <path>
                        <groupId>org.mapstruct</groupId>
                        <artifactId>mapstruct-processor</artifactId>
                        <version>${mapstruct.version}</version>
                    </path>
                </annotationProcessorPaths>
                <compilerArgs>
                    <arg>-Amapstruct.defaultComponentModel=spring</arg>
                </compilerArgs>
            </configuration>
        </plugin>
    </plugins>
</build>
```

<details>
<summary>💡 What does defaultComponentModel=spring do?</summary>

This tells MapStruct to generate mappers as Spring `@Component` beans, allowing you to inject them with constructor injection.

</details>

### 1.3 Create UserMapper

**File:** `user-service/src/main/java/com/dornach/user/mapper/UserMapper.java`

```java
package com.dornach.user.mapper;

import com.dornach.user.domain.User;
import com.dornach.user.dto.CreateUserRequest;
import com.dornach.user.dto.UpdateUserRequest;
import com.dornach.user.dto.UserResponse;
import org.mapstruct.Mapper;
import org.mapstruct.Mapping;
import org.mapstruct.MappingTarget;

@Mapper(componentModel = "spring")
public interface UserMapper {

    UserResponse toResponse(User user);

    @Mapping(target = "id", ignore = true)
    @Mapping(target = "status", ignore = true)
    @Mapping(target = "createdAt", ignore = true)
    @Mapping(target = "updatedAt", ignore = true)
    User toEntity(CreateUserRequest request);

    @Mapping(target = "id", ignore = true)
    @Mapping(target = "email", ignore = true)
    @Mapping(target = "status", ignore = true)
    @Mapping(target = "createdAt", ignore = true)
    @Mapping(target = "updatedAt", ignore = true)
    void updateEntity(UpdateUserRequest request, @MappingTarget User user);
}
```

<details>
<summary>💡 Understanding the annotations</summary>

| Annotation | Purpose |
|------------|---------|
| `@Mapper(componentModel = "spring")` | Makes the mapper a Spring bean |
| `@Mapping(target = "id", ignore = true)` | Don't map this field (auto-generated by DB) |
| `@MappingTarget` | Update an existing object instead of creating new |

</details>

### 1.4 Update UserService

Inject the mapper and use it for entity creation:

**File:** `user-service/src/main/java/com/dornach/user/service/UserService.java`

```java
@Service
public class UserService {

    private final UserRepository userRepository;
    private final UserMapper userMapper;  // Add this

    public UserService(UserRepository userRepository, UserMapper userMapper) {
        this.userRepository = userRepository;
        this.userMapper = userMapper;  // Add this
    }

    public User createUser(CreateUserRequest request) {
        if (userRepository.existsByEmail(request.email())) {
            throw new EmailAlreadyExistsException(request.email());
        }
        User user = userMapper.toEntity(request);  // Use mapper instead of manual mapping
        user.setStatus(UserStatus.ACTIVE);
        return userRepository.save(user);
    }

    // Update other methods similarly...
}
```

### 1.5 Update UserController

Replace manual mapping with the mapper:

**File:** `user-service/src/main/java/com/dornach/user/controller/UserController.java`

```java
@RestController
@RequestMapping("/users")
public class UserController {

    private final UserService userService;
    private final UserMapper userMapper;  // Add this

    public UserController(UserService userService, UserMapper userMapper) {
        this.userService = userService;
        this.userMapper = userMapper;  // Add this
    }

    @GetMapping
    public List<UserResponse> getAllUsers() {
        return userService.getAllUsers().stream()
                .map(userMapper::toResponse)  // Use mapper
                .toList();
    }

    @PostMapping
    public ResponseEntity<UserResponse> createUser(@RequestBody @Valid CreateUserRequest request) {
        User user = userService.createUser(request);
        return ResponseEntity.status(HttpStatus.CREATED)
                .body(userMapper.toResponse(user));  // Use mapper
    }

    // Update other methods similarly...
}
```

### 1.6 Remove Manual Mapping Methods

You can now remove the `from()` method from `UserResponse.java` since MapStruct handles the mapping.

### 1.7 Build and Verify

```bash
# Compile to generate mapper implementation
mvn clean compile -pl user-service

# Check generated code (optional)
cat user-service/target/generated-sources/annotations/com/dornach/user/mapper/UserMapperImpl.java

# Run tests
mvn test -pl user-service
```

The generated `UserMapperImpl.java` contains the same code you would have written manually, but without the effort.

## Exercise 2: Custom Mapping Methods

Sometimes you need computed fields that don't exist in the source. Let's add a `fullName` field to `UserResponse`.

### 2.1 Add fullName to UserResponse

**File:** `user-service/src/main/java/com/dornach/user/dto/UserResponse.java`

```java
public record UserResponse(
    UUID id,
    String email,
    String firstName,
    String lastName,
    String fullName,  // New computed field
    UserRole role,
    UserStatus status,
    Instant createdAt,
    Instant updatedAt
) {}
```

### 2.2 Add Custom Mapping Method

Update the mapper to compute `fullName`:

**File:** `user-service/src/main/java/com/dornach/user/mapper/UserMapper.java`

```java
@Mapper(componentModel = "spring")
public interface UserMapper {

    @Mapping(target = "fullName", source = "user", qualifiedByName = "mapFullName")
    UserResponse toResponse(User user);

    @Named("mapFullName")
    default String mapFullName(User user) {
        return user.getFirstName() + " " + user.getLastName();
    }

    // ... rest of the mapper unchanged
}
```

Don't forget to add the import:
```java
import org.mapstruct.Named;
```

### 2.3 Test the Custom Mapping

```bash
# Recompile
mvn clean compile -pl user-service

# Start the service and test
mvn spring-boot:run -pl user-service
```

The API response should now include the `fullName` field.

<details>
<summary>💡 Alternative: Using expression</summary>

You can also use Java expressions directly:

```java
@Mapping(target = "fullName",
         expression = "java(user.getFirstName() + \" \" + user.getLastName())")
UserResponse toResponse(User user);
```

The `@Named` approach is cleaner for complex logic.

</details>

## Troubleshooting

### "No implementation was created for UserMapper"

The annotation processor is not configured. Verify:
```xml
<annotationProcessorPaths>
    <path>
        <groupId>org.mapstruct</groupId>
        <artifactId>mapstruct-processor</artifactId>
        <version>${mapstruct.version}</version>
    </path>
</annotationProcessorPaths>
```

### "Unmapped target property" warning

MapStruct warns about fields it can't map. Either:
- Add `@Mapping(target = "fieldName", ignore = true)`
- Or ensure source has a matching field

### IDE doesn't recognize generated code

Run `mvn compile` first, then refresh your IDE. For IntelliJ, enable annotation processing in settings.

### Why MapStruct over alternatives?

| Approach | Speed | Type Safety | Maintenance |
|----------|-------|-------------|-------------|
| Manual | Fast | Compile-time | High effort |
| MapStruct | Fast | Compile-time | Low effort |
| ModelMapper | Slow (reflection) | Runtime | Medium effort |

**MapStruct is the recommended approach** for production Spring Boot applications.
